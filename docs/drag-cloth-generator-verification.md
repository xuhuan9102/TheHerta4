# 拖拽生成器检查（2026-11-15）

用户已确认当前「蕾米埃尔·月夜密语」效果暂时可用。本次整理并验证生成器，保持现有穿脱行为，
不把生成检查通过解释成任意姿态都无穿模。

## 修正与整理

- 普通碰撞与穿脱独立生成，区域衣物/身体选择、行程箭头、左右袜与双腿短裤分区保留。
- 停住或松手冻结最后模拟网格，动作仅输送蒙皮；两个绘制槽分别保存代理和显示缓存。
- 修正接触查询失败时旧双腿缓存仍可被重新提交的问题；先验证失败用例，再修正并通过回归。
- 修正D3D11检查工具对普通拖拽组件的初始化兼容，未启用穿脱时不要求穿脱组件元数据。
- 参数说明与当前调度保持一致。当前指南、设计决策和历史候选记录分开。
- 增加`tools/check_drag_cloth_export.py`，重复检查产物哈希、文件/衣物段引用、缓冲容量、写回别名和活动CS编译。

## 重复检查

当前配置与计算流程见[使用说明](drag-cloth.md)，产物可独立运行：

```powershell
python tools/check_drag_cloth_export.py MOD_DIRECTORY --compile --report export-audit.json
python tools/check_drag_cloth_mesh.py replay.npz --report mesh-audit.json
python -m unittest tests.test_drag_cloth_export tests.test_drag_buffer_bindings tests.test_drag_feature_switches
```

`export-audit.json`只表示包结构和着色器检查，`geometry_certified`始终为false；
实际形变需另行回放，网格检查失败时不能用编译成功覆盖结果。

## 2026-11-17：普通模式Alt显示修正

普通拖拽的临时绘制缓冲曾按可见顶点数固定容量。它与原生SO容量不一致时，加载器
的整块复制失败；穿脱另有有效范围复制路径，因此可能出现只在普通模式按Alt消失。
当前生成器改为继承原生容量，保持派发按可见顶点数计算，产物检查同时拒绝固定容量。

回放工具也按加载器规则处理隐式复制、空绑定及随容量变化的临时副本。新增D3D11回归
覆盖容量增长/缩小、普通和显式复制、源数据不变与完整回写。两组相关回归分别113项、
232项通过（包含重叠用例）。当前模组的实际普通计算段在13715、14739、12691行容量
下均逐字节保留了测试输入；旧配置在第一种容量即报复制尺寸不匹配。该回放构造正常
原生输入，不代表读取了当前游戏的实时顶点或已完成游戏内重载验收。

随后游戏反馈为“显示正常但没有变形”。实际抓帧`2026-11-17-055758`确认：原生容量
20274行、显示顶点12691行；计算后1650点移动，碰撞后1502点移动，但原复制回写的
显示缓冲与输入逐字节相同。新链将计算和碰撞写入命名结构化缓冲，用typed UAV发布
最终位置，避免依赖该复制回写。以此真实输入和状态重放，最终1502点的位置与抓帧
的碰撞修正结果完全一致，法线/切线等其他属性保持原输入值；临时快照安装段已撤下。

另补齐回放工具的内联`data`资源初始化，避免对象参数被错误清零，掩盖实际抓取位移。
屏幕基向量的第9行w分量是检测条件值，不是布尔标记；消费侧改用检测器相同的1e-5
阈值，回归覆盖有效的0.2条件值及无效的退化值。此次实际抓帧条件值接近1，后者不是
本次丢失显示位移的原因。

上述首次GPU发布候选在游戏里再次导致消失，已撤回。最终普通输出采用与穿脱相同的
初始化协议：原生完整快照保持动态容量，用uint种子CS初始化固定可见输出；结构化
`Solved`只作为计算结果，发布CS从它读取坐标并写入绘制输出。源头不再把原生SO
整块复制到UAV/VB输出，也不从结构化结果整块复制回VB。原生法线/切线由种子复制
保留。旁路探针已撤回；真实输入重放仍保持1502个变形点与捕获结果一致。

用户随后确认该种子初始化版本在游戏中“人物显示正常，拖拽也正常”。生成器又使用
原审查工程、新预处理缓存完整导出一次，无导出警告且原工程不变。新产物的5份关键
缓冲声明、Seed/Publish段、计算顺序和3份相关着色器文本均与游戏验收版一致；
把同一真实抓帧输入送入新生成产物，最终1502点仍与捕获的求解位置完全一致。
相关270项回归通过；旧缓冲家族在重生成时整体移除重建，防止旧声明与新着色器混用。
