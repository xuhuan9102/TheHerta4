# ZZMI 定身功能设计（CB1 快照）

2026-11-24，仪玄·墨形影踪的实机原型已验证。CB1 快照已接入骨骼矩阵控制节点的 ZZMI 导出。

## 开关行为

骨骼矩阵控制节点的 **定身（CB1 快照）** 区域有两个输入框。开关变量默认是 `$bone_matrix_cb1_lock`，快捷键默认是 `Ctrl+Alt+B`。定身默认关闭，快捷键留空时由开关变量控制。

动画骨架列表留空时，导出只生成 CB1 定身控制。添加骨架项后，可在该项里选择骨架并配置动画挂接。

| 操作 | 游戏中的行为 |
| --- | --- |
| 开启 | 在目标角色实例下一次参与渲染的帧，捕获同一帧内各目标绘制绑定的整块 `vs-cb1`。捕获完成后，以该帧的世界位置和朝向显示模型。 |
| 保持开启 | 目标绘制持续使用快照。游戏、相机和角色控制照常运行。骨骼动画继续由播放开关和播放帧控制，可以在固定位置播放自定义动作。 |
| 关闭 | 恢复实时 CB1 和实时坐标校准，本次快照失效。 |
| 再次开启 | 从新的当前渲染帧取得快照，更新定身位置和朝向。 |

## 捕获与绘制

渲染阶段的 `vs-cb1` 包含对象到世界的变换。全量替换骨骼矩阵可以控制蒙皮姿态。模型整体位置和朝向还由渲染时的对象变换决定。若只缓存已蒙皮的顶点，实时对象变换仍会作用在这些顶点上，实测跑步时曾出现整个模型前倾。

1. 按模组对应的 IB、起始索引、索引数和实际蒙皮输出关联目标实例。对同一实例分别记录各部件、绘制通道和 CB1 的绑定范围。不同部件和通道可以使用不同长度的 CB1。
2. 开关从关到开时，为各匹配绘制复制顶点着色器实际可见的**整个 CB1 字节区间**，包括对象矩阵以外的参数。记录绑定的偏移和长度，快照的缓冲长度跟随实际布局。快照与当帧用于蒙皮的世界空间基准一起保存。
3. 对每笔命中的绘制，先保存它的原始 CB1 绑定，再绑定对应的私有快照。蒙皮以冻结后的对象变换及同一帧基准换算空间，当前播放帧的自定义骨骼矩阵仍参与计算。绘制沿用游戏原有的提交，结束后恢复原缓冲及其绑定范围。
4. 同屏角色各自管理快照。切换服装、实例或遇到关键通道布局变化时，失效的实例回到实时路径，重新开启后再取快照。应记录取样不完整或布局变化，方便检查局部漂移。

CB1 整块固定也会保留捕获时的其他常量。通用导出前，还要核验不同场景和渲染通道里的阴影、运动矢量和镜头变化。

## 实机结果

2026-11-24，在大世界对仪玄·墨形影踪开启整块 CB1 快照。用户确认人物留在捕获位置。身体的实时 CB1 在两轮取样之间仍旋转约 **3.93°**，实际提交绘制的 CB1 旋转变化为 **0°**。下表记录六组网格各一笔已采样绘制，两次完整 CB1 的 SHA-256 一致。

原型抓取记录文件名为 `apos-whole-cb1-freeze-live.json`。表中的帧号、字节数与哈希来自该次抓取。

## 功能验收

- 角色显示页和大世界中都能在当前位置开启定身。开启后移动角色控制或转镜头，目标模型保持快照时的世界位置和朝向。
- 定身时更改播放帧，完整或局部骨骼动画在固定位置正常播放，身体、主脸和辅助脸保持对齐。
- 关闭后恢复游戏实时位置和朝向。移动到新位置再次开启，模型固定在新的位置。
- 同屏其他角色及共用骨架的其他服装继续正常渲染。检查两种原始索引提交、各关键通道的 CB1 布局和绘制结束后的绑定恢复。
