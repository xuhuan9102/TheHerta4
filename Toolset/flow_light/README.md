# 模型流光

节点在选中的角色物体完成正常材质绘制后，复用当前顶点着色器与投影，以深度相等测试叠加流光。效果会随角色界面的后续转绘一起变换，并参与游戏的后处理。

- **边缘流光**：根据表面法线与视线夹角生成边缘光，位于模型表面内侧，不是外扩的像素轮廓。
- **表面流光**：光带扫过模型表面。
- **边缘 + 表面**：两者叠加；「表面强度」控制表面部分，「边缘收紧」越大，边缘光越窄。

扫光使用游戏模型的局部坐标，默认沿 Z 轴扫描 `0..1.8`。按模型实际高度调整起点/终点；旋转镜头不会改变光带附着位置。向下/向上选项翻转扫描坐标，光带在两个端点间往返。

导出需要 Windows 自带的 `d3dcompiler_47.dll`。当前实现不生成全局 ShaderRegex：通过已验证的 ZZZ 正常材质 VS 哈希 `c280f6945b23a42a` 设置临时通道标记，不改变原 shader 或 filter_index；只有当前角色的 TextureOverride 已命中、该标记有效、四个 MRT 与深度目标齐全时，才在所选 mesh 后绘制流光。角色标记每帧清零，通道标记在原绘制结束后清零，借用的 ini 参数在叠加结束后恢复。

流光不写深度，目标 0 只累加 RGB 并保留 alpha，目标 1～3 累加零。此方式适合正常写深度的模型表面；不写深度的特殊透明材质需要单独适配。游戏更新导致正常材质 VS 哈希或布局改变时，应重新验证并适配；不匹配时不会启用流光。

旧屏幕描边已移除。已有工程再次导出时，会清理对应 tag 的旧遮罩、JFA、Present 合成段及着色器文件，统一生成模型流光。

验证：`python -m pytest tests/test_flow_light_core.py tests/test_flow_light_material.py tests/test_node_postprocess_flow_light.py -q`。导出时编译实际叠加着色器，并核对输入寄存器和四个 MRT 输出；离线检查不替代游戏画面验收。
